## 1. Why this experiment replaces the earlier per-model results

Each group member first developed their model independently, and in doing so explored
different numbers of configurations: the Simple RNN was searched across fourteen, the LSTM
across two, and the GRU and 1D CNN were each trained once. All selection was performed on
validation data, so no test leakage occurred. However, **the amount of tuning a model
receives affects its score just as the architecture does**. Comparing a model tuned fourteen
times against one trained once does not isolate the architecture.

The four models were also trained on four different machines, so the wall-clock training
times recorded in the individual notebooks cannot be compared with one another.

This chapter therefore reports a **final controlled experiment** in which all four
architectures are trained under one common configuration, in a single session, on a single
machine, and evaluated on the same test reviews. The earlier per-model development work is
retained in the individual model folders as a record of the process, but none of its
model-specific hyperparameter choices are active in the comparison reported here.

## 2. Experimental setup

### 2.1 Common training configuration

Every value below is applied identically to all four models. None is overridden per model.

| Setting | Value |
|---|---|
| Loss function | Binary crossentropy |
| Output activation | Sigmoid, 1 unit |
| Optimiser | Adam |
| Learning rate | 0.001 |
| Batch size | 32 |
| Maximum epochs | 30 |
| Early stopping monitor | `val_loss` |
| Early stopping patience | 5 |
| Weight restoration | `restore_best_weights=True` |
| Classification threshold | 0.5 |
| Random seed | 42, re-applied immediately before each model is built |
| Class weights | 1.003145 (negative), 0.996875 (positive), from training labels only |

### 2.2 Common data pipeline

The data is prepared by a **single** call to `shared.data_pipeline.prepare_data()`, and the
resulting arrays are passed to all four models. The split, vocabulary, padding and class
weights are therefore not merely equivalent between models — they are the same objects.

| Property | Value |
|---|---|
| Dataset | `dataset/deceptive-opinion.csv`, 1,596 reviews after removing 4 exact duplicates |
| Target | `polarity`; negative = 0, positive = 1 |
| Cleaning | lowercase, normalise apostrophes, strip HTML, strip URLs, expand contractions, remove non-letters, collapse whitespace |
| Stop-words | **retained** — removing them would delete `not`, `no`, `never`, which invert sentiment |
| Tokenisation | whitespace split on the cleaned text |
| Vocabulary | 5,000 entries, built from **training rows only**; `<PAD>` = 0, `<OOV>` = 1 |
| Sequence length | `MAX_LEN` = 300, pre-padding, post-truncation |
| Embedding | `Embedding(5000, 64)`, randomly initialised and learned; no pre-trained vectors |
| Split | 80 / 10 / 10 stratified — 1,276 train, 160 validation, 160 test |

The `deceptive` column is **not** used as an input feature or as a target. It is carried
through to the prediction files for error analysis only, and never reaches the model.

### 2.3 Architectures — the only variable

All four share the identical embedding and the identical classification head. Only the
sequence-processing layers differ.

| Model | Full layer stack | Parameters |
|---|---|---|
| Simple RNN | `Embedding(5000,64) → SimpleRNN(64, return_sequences=True) → GlobalAveragePooling1D → Dense(32, relu) → Dropout(0.3) → Dense(1, sigmoid)` | 330,369 |
| LSTM | `Embedding(5000,64) → LSTM(64) → Dense(32, relu) → Dropout(0.3) → Dense(1, sigmoid)` | 355,137 |
| GRU | `Embedding(5000,64) → GRU(64) → Dense(32, relu) → Dropout(0.3) → Dense(1, sigmoid)` | 347,073 |
| 1D CNN | `Embedding(5000,64) → Conv1D(128, kernel_size=5, relu) → GlobalMaxPooling1D → Dense(32, relu) → Dropout(0.3) → Dense(1, sigmoid)` | 365,249 |

The embedding accounts for 87.6% to 96.9% of each model's parameters, and it is identical in
all four. The models therefore differ by at most 10% in total capacity, which supports
attributing performance differences to the architecture rather than to model size.

### 2.4 Prevention of data leakage

| Safeguard | Implementation |
|---|---|
| Duplicates removed before splitting | `drop_duplicates` precedes split assignment, so no review appears in two partitions |
| Vocabulary from training rows only | `build_vocab(parts["train"]["tokens"])`; OOV rate rises from 1.81% in training to 3.16% in test, confirming this |
| Class weights from training labels only | `compute_class_weights(y_train)` |
| Early stopping on validation | `validation_data=(X_val, y_val)`, `monitor="val_loss"` |
| Test set used once | `model.predict(X_test)` runs only after training completes, once per model |
| No model selection on test | The configuration is fixed in advance; nothing is chosen using test results |

### 2.5 Computational environment

| Component | Value |
|---|---|
| CPU | Apple M4, 10 physical cores |
| Memory | 16 GB |
| Accelerator | None — CPU only |
| Operating system | macOS 26.2 (arm64) |
| Python | 3.12.13 |
| TensorFlow | 2.21.0 |
| Keras | 3.15.1 |
| NumPy / pandas / scikit-learn | 2.5.3 / 3.0.6 / 1.9.1 |

All four models in this experiment were trained in one session on this one machine, so their
training times are comparable **with each other**. They are not comparable with the times in
the earlier per-model notebooks, which ran on different machines.

### 2.6 Evaluation metrics

Computed on the 160-review test partition at threshold 0.5, using one shared
`compute_metrics()` function: accuracy, precision, recall, F1-score, ROC-AUC and the
confusion matrix. Each metric is accompanied by a 95% bootstrap confidence interval from
2,000 resamples with a fixed seed. Because all four models predict on the identical reviews,
the comparison is paired and **McNemar's exact test** is applied to every pair.

## 4. Interpretation

**No architecture is demonstrably better than the others on this task.** The Simple RNN
attains the highest accuracy (0.9250) and the 1D CNN the lowest validation loss (0.1463) and
the highest recall (0.9500), but the spread across all four is 3.75 percentage points — six
correct predictions out of 160 — and McNemar's test rejects none of the six pairwise
comparisons. The correct conclusion is that the four architectures perform comparably here.

This is a credible outcome rather than a failed experiment. The corpus is small and balanced,
the reviews are long and lexically explicit, and much of the sentiment signal is carried by
individual words such as *worst*, *rude* and *filthy*. A task of that character does not
require long-range sequential modelling, so the theoretical advantages of gated recurrence
have little room to show themselves.

**The models make different kinds of error.** The LSTM is the most conservative — 4 false
positives but 14 false negatives, so it misses genuinely positive reviews. The 1D CNN is the
opposite, with 11 false positives and only 4 false negatives, giving it the best recall and
the worst precision. If the application were flagging dissatisfied guests for follow-up, the
CNN's error profile would be preferable even though its accuracy is not the highest. This
distinction is invisible in the accuracy column and is the more useful finding.

**Early stopping terminated the models at different epochs**, and this is a legitimate
outcome of the common procedure rather than a confound. The GRU reached its best validation
loss at epoch 3 and stopped at 8; the Simple RNN and 1D CNN needed until epoch 8 and stopped
at 13. Each model trained until its own validation loss stopped improving.

**Training time is an implementation observation, not a result.** The 1D CNN is the fastest
at 4.54 s, which is consistent with convolution parallelising across the sequence while a
recurrent layer must process 300 timesteps in order. That is an argument from architecture.
The measured times support it but do not establish it, and they are not used to rank the
models. In particular, **no claim is made that the GRU or the 1D CNN is "better" because it
trained faster** — model quality is assessed on the test metrics alone.

## 5. Limitations

1. **The test set is small.** 160 reviews means one additional correct prediction moves
   accuracy by 0.625 points. Differences of two or three points cannot be resolved, which is
   what the significance testing shows.

2. **A single seed.** The headline figures come from seed 42, fixed in advance. Multi-seed
   robustness for individual models is reported in the per-model notebooks; the controlled
   experiment reports one seed per architecture so that all four are compared under exactly
   the same conditions.

3. **The Simple RNN uses a different readout.** It applies `GlobalAveragePooling1D` over the
   full sequence, whereas the LSTM and GRU use the final hidden state. This is a deliberate
   mitigation of the recency bias of a simple recurrent cell, but it does mean the Simple RNN
   differs from the other two recurrent models in more than just the cell type.

4. **One dataset and one domain.** All 1,596 reviews come from 20 Chicago hotels. The
   conclusions may not transfer to other domains or to shorter review text.

5. **No hyperparameter optimisation in the final comparison.** Every model uses the same
   fixed configuration. A model whose best configuration happens to lie further from these
   defaults is disadvantaged, and a like-for-like tuned comparison would require giving each
   architecture an identical search budget — which was outside the scope of this experiment.

## 6. Reproducibility

```bash
python final_experiment/run_final_experiment.py   # trains all four, writes every artifact
python final_experiment/verify_fairness.py        # 31 automated fairness checks
```

The verification script re-derives every fairness claim in Section 2 from the files on disk:
identical test indices and labels across models, identical preprocessing constants, identical
optimiser, learning rate, batch size, epoch cap, early-stopping patience, class weights and
threshold, and metrics recomputed from the saved predictions. All 31 checks pass.

Running the experiment twice produces byte-identical metrics. Only wall-clock times vary,
by a few tenths of a second.
